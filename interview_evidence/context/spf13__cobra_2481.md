## 1. Problem Summary & Objective
> The PowerShell autocompletion script generated by Cobra crashes with runtime errors when a command returns no completions or only a single completion. This happens because PowerShell automatically converts single-item arrays into scalar strings, causing index operations to return characters instead of strings, and because empty outputs lead to null-pointer exceptions.

## 2. Root Cause Analysis
> In powershell_completions.go (lines 130-140), the script executes the completion command and stores the result in $Out. If the command fails or returns nothing, $Out is empty/null, and calling $Out[-1].TrimStart(':') fails. If the command returns exactly one line, PowerShell's pipeline unwraps the array into a scalar System.String. Accessing $Out[-1] on a string returns its last character (System.Char), which does not have a TrimStart method. Furthermore, using Where-Object { $_ -ne $Out[-1] } to remove the directive filters by value equality, which incorrectly strips any legitimate completion items that match the directive string.

## 5. Educational Concepts
### PowerShell Array Unwrapping
- **What is it:** PowerShell automatically unwraps single-element arrays into scalar objects (like a single String) when passed through pipelines or returned from expressions.
- **Why it matters:** Developers writing PowerShell scripts must be aware of this behavior because indexing a scalar string ($Out[-1]) returns a System.Char instead of a System.String, which lacks string-specific methods like TrimStart.
- **Connection to Issue:** This unwrapping is the direct cause of the 'Method invocation failed because [System.Char] does not contain a method named 'TrimStart'' error when only one completion item is returned.

### Safe Array Slicing and Filtering
- **What is it:** Removing elements from an array should be done by index or position (e.g., using Select-Object -First) rather than filtering by value, unless value-based removal is explicitly desired.
- **Why it matters:** Filtering by value can accidentally remove duplicate or identical legitimate data elements from a collection, whereas positional slicing guarantees only the intended element is removed.
- **Connection to Issue:** The current script uses Where-Object to filter out the directive, which accidentally removes any completion item that matches the directive's string value. Using Select-Object avoids this collision.
